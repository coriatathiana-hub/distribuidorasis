# Objective: HU-5.3 — Permitir relacion producto multi-categoria con migracion de modelo y UI admin/publica

## Context
- **Feature:** FEAT-5 — Hardening post-MVP de conversion, edicion y taxonomia de catalogo
- **Branch:** `hu/5.3`
- **Story:** Como Admin de catalogo, quiero asociar un producto a mas de una categoria, para poder representar mejor el catalogo y mejorar descubrimiento por distintos criterios.
- **Spec Level:** Standard (Complex Story, riesgo alto)
- **Dependencies:** HU-2.3 (CRUD base catalogo), HU-2.4 (layout/rutas admin), HU-3.1 (reglas de galeria), HU-5.1 (acceso por modulo)
- **Design Artifact:** `.spec/work/FEAT-5/HU-5.3_ADR.md`

## Acceptance Criteria (BDD)
- **Dado que** el modelo actual usa `products.category_id`, **cuando** se aplica la migracion a tabla pivote `product_categories`, **entonces** los productos existentes conservan su categoria original sin perdida de datos.
- **Dado que** un admin crea o edita un producto, **cuando** selecciona multiples categorias validas, **entonces** el producto queda visible en todos los filtros publicos de esas categorias.
- **Dado que** la migracion detecta referencias huerfanas o categorias inactivas incompatibles, **cuando** se ejecuta el script, **entonces** el proceso se detiene con reporte y sin cambios parciales.

## Database Changes (Draft SQL)

```sql
-- Migration draft for HU-5.3 (to be finalized in 009 migration)
create table if not exists public.product_categories (
  product_id uuid not null references public.products(id) on delete cascade,
  category_id uuid not null references public.categories(id) on delete restrict,
  created_at timestamptz not null default now(),
  primary key (product_id, category_id)
);

create index if not exists idx_product_categories_category_id
  on public.product_categories (category_id);

insert into public.product_categories (product_id, category_id)
select p.id, p.category_id
from public.products p
where p.category_id is not null
on conflict (product_id, category_id) do nothing;
```

## Risks and Mitigations
- **Data integrity risk:** prevenir duplicados y huerfanos con PK compuesta, FKs y rollback transaccional.
- **Compatibility risk:** mantener columna legacy temporalmente hasta migrar todos los consumers.
- **Security risk:** incluir policies RLS para `product_categories` antes de exponer lecturas publicas.
- **Regression risk:** cubrir listados/filtros/detalle con pruebas de integracion.
