# Objective: HU-5.6 — Hardening de trazabilidad para WhatsApp CTA con persistencia confiable en `whatsapp_cta_attempts`

## Context
- **Feature:** FEAT-5 — Hardening post-MVP de conversion, edicion y taxonomia de catalogo
- **Story:** Como responsable comercial y administrador de conversiones, quiero que cada clic valido al CTA de WhatsApp quede trazado de forma confiable, para poder usar el dashboard de conversion con datos consistentes para seguimiento comercial.
- **Spec Level:** Lite (simple story de hardening/bugfix)
- **Branch:** `hu/5.6`
- **Dependencies:** HU-4.3 (tracking base WhatsApp), HU-4.4 (dashboard de conversion), HU-5.1 (acceso admin por modulo)
- **tdd_mode:** `flexible` (`IMPLEMENT → TEST → REFACTOR`)

## Acceptance Criteria (BDD)
1. Persistencia confiable de intentos WhatsApp en escenarios reales.
   - **Dado que:** Un usuario hace clic en un CTA de WhatsApp desde el sitio.
   - **Cuando:** Se dispara el tracking del intento.
   - **Entonces:** El evento se persiste en `whatsapp_cta_attempts` con `source`, `context_type`, `opened_successfully` y `created_at`.

2. Recuperacion ante fallo transitorio sin bloquear UX.
   - **Dado que:** Existe un fallo transitorio de red o cambio inmediato de contexto del navegador.
   - **Cuando:** Falla el primer intento de persistencia.
   - **Entonces:** El sistema ejecuta la estrategia de recuperacion definida sin bloquear la accion del usuario.

3. Umbral operativo de consistencia para medicion comercial.
   - **Dado que:** Se ejecutan pruebas controladas de conversion.
   - **Cuando:** Se comparan clics instrumentados contra registros persistidos.
   - **Entonces:** La desviacion permanece dentro del umbral operativo acordado.

- **Escalated ADRs:** None
- **Lesson:** For browser-exit sensitive telemetry, prioritize idempotent writes and non-blocking retry strategy at service boundary before touching UI layers.
